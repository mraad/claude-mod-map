ArcGIS Map Mod

A Claude Code mod. Claude puts graphics and layers on a live ArcGIS Maps SDK for JavaScript 5.2 map. You see the map in the Claude Code pane, in a browser window, or in both.

1. Purpose

The mod connects Claude to a map. You write a request in Claude Code. Claude calls a map tool. The map shows the result.

The mod does these tasks:

  • It adds points, lines and polygons as graphics.
  • It adds layers from services, GeoJSON files, GeoParquet files and portal items.
  • It moves the map to a location or to a layer.
  • It gives Claude the current map state.

2. Terms

This document uses each term below with one meaning only.

TermMeaning

BridgeThe local HTTP server web/server.mjs. It listens on 127.0.0.1:8765. The mod starts it.

PaneThe panel on the right side of Claude Code. The mod draws the map in it as pictures.
Browser windowA Chrome app window that shows the map page. It has no tabs and no toolbar.
ViewerA headless Chrome that shows the map page for the pane. The module web/viewer.mjs controls it.

Graphics layerA layer that holds graphics. A tool makes it when it does not exist.

3. Requirements

  • macOS. The Chrome path and the GPU flags are for macOS.
  • Claude Code v2.1.287 or later. Mods need this version.
  • Node.js 22 or later. The bridge uses only the Node standard library.
  • Google Chrome in /Applications/Google Chrome.app. Set the variable CHROME for a different path.
  • A network connection. The map page loads the SDK from js.arcgis.com and basemap tiles from the internet.
  • For the pane only: a terminal that shows pictures. Ghostty and kitty do. iTerm2 does in fullscreen mode.

The mod has no npm dependencies. The default basemap is OpenStreetMap. Six basemaps need no API key (section 7.1).

4. Start the mod

A mod is code that runs with your permissions inside Claude Code. Install mods only from authors and marketplaces that you trust. Read the code of this mod before you install it.

4.1 Install from the repository

  1. Start Claude Code.
  2. Type /plugin install arcgis-map --marketplace mraad/claude-mod-map.
  3. Push Enter.
  4. Type y to add the marketplace.
  5. Select a scope.

From a shell, use this command: claude plugin install arcgis-map --marketplace mraad/claude-mod-map.

4.2 Start Claude Code with a local copy

Use this procedure to change the mod.

  1. Type git clone https://github.com/mraad/claude-mod-map.git.
  2. Type cd claude-mod-map.
  3. Type claude --plugin-dir ./arcgis-map.

The mod starts the bridge when the session starts. The bridge stops when the session stops.

5. Open the map

The command /map opens the map. It takes one optional word.

CommandResult
/mapOpens the map in the pane.
/map paneOpens the map in the pane.
/map browserOpens the map in a browser window on the right half of the screen that has the focus.
/map clearRemoves all layers and graphics. Sets the basemap to OpenStreetMap. Keeps the view. Claude does not do a turn for this command.
/map stopStops the map server. Closes the pane and the browser window. Type /map or /map browser to start the map again. The map keeps its layers.
/map with a different wordShows the usage line Usage: /map [pane|browser|clear|stop].

You can open the pane and the browser window at the same time. Each tool changes both. You can also open http://127.0.0.1:8765/ in any browser.

5.1 Open the map in the pane

  1. Type /map.
  2. Push Enter.

The pane shows "starting the map…". The first frame comes in approximately 1.5 seconds.

5.2 Open the map in a browser window

  1. Type /map browser.
  2. Push Enter.

The window uses its own Chrome profile in the folder .browser-profile of the mod. The mod does not move or resize the Ghostty window.

7.1 Keyless basemaps

set_basemap accepts these six ids without an API key. Each Esri basemap uses raster tiles from https://services.arcgisonline.com/arcgis/rest/services/<service>/MapServer.

IdBase tilesLabel tiles
osmOpenStreetMap. This is the default basemap.None. The labels are in the base tiles.
dark-grayCanvas/World_Dark_Gray_BaseCanvas/World_Dark_Gray_Reference
light-grayCanvas/World_Light_Gray_BaseCanvas/World_Light_Gray_Reference
imageryWorld_ImageryReference/World_Boundaries_and_Places
topoWorld_Topo_MapNone.
streetsWorld_Street_MapNone.

The label tiles are a reference layer of the basemap. The map shows them above all layers.

Use set_basemap to change the basemap. Do not add a basemap service with add_layer. A tile layer from add_layer is a usual layer: it is in the layer list, it covers the basemap, and layers that you add later cover its labels.

An Esri basemap style, for example arcgis/topographic, needs an API key. Open the map page with ?apiKey=<key>. Without a key, set_basemap refuses the style immediately.

When the basemap changes, the map has no zoom levels for a short time. The view shows zoom -1 during this time. set_basemap answers only when the zoom is 0 or more again.

8. Examples

8.1 Markers, labels and a route

Request: "Create markers in Sydney, Dubai, Beirut, Florence, Paris, New York and San Francisco. Label each one. Connect them with a geodesic line. Make the basemap dark. Put everything in one GeoJSON document."

The file examples/cities-route.geojson is that document. It is one FeatureCollection with 8 features: 7 Points (name, kind: "city", order) and 1 LineString (kind: "route", stops, length_km: 27397). A GeoJSON line is straight in longitude and latitude. To make it geodesic, the file has 32 points on the great circle for each segment.

Claude makes these calls:

  1. Seven add_graphic calls with Point geometry in the layer "Cities".
  2. Seven add_graphic calls with a text symbol in the layer "Labels".
  3. One add_graphic call with the LineString of the file in the layer "Route".
  4. One go_to call with layerId: "Route".

8.2 A dark basemap

Claude calls set_basemap with dark-gray. This basemap uses the Esri Dark Gray Canvas tiles from services.arcgisonline.com. It needs no API key. The layers stay on top.

8.3 A filtered feature layer

Request: "Add the World Countries layer filtered to Kuwait."

add_layer {
  "type": "feature",
  "url": "https://services.arcgis.com/P3ePLMYs2RVChkJx/arcgis/rest/services/World_Countries_(Generalized)/FeatureServer/0",
  "definitionExpression": "COUNTRY = 'Kuwait'"
}

The map zooms to the extent of the filtered features. It uses queryExtent(), not fullExtent.

8.4 A local GeoParquet file

add_layer { "type": "parquet", "path": "/data/sites.parquet", "title": "Sites (GeoParquet)" }

The file examples/cities.parquet is a sample: the seven cities of section 8.1 as GeoParquet with Snappy compression. duckdb wrote it.

The map zooms to the features that agree with the filter (definitionExpression).

GDAL 3.13 (ogr2ogr -f Parquet) writes no crs for WGS84. The map then uses the GeoParquet default, OGC:CRS84 (wkid 4326). A file that has its own crs keeps it.

The bridge serves the file at a random URL, with HEAD and Range support. ParquetLayer reads the file. The file must use GZIP, Snappy or no compression.

8.5 Analysis results

Request: "Show the three cities with their scores. Color them by score and label them."

Claude sends all features in one call. It does not send one add_graphic call for each feature.

add_layer {
  "type": "geojson",
  "title": "Gulf cities",
  "data": { "type": "FeatureCollection", "features": [ ... ] },
  "renderer": { "type": "class-breaks", "field": "score", "classBreakInfos": [ ... ] },
  "labelingInfo": [{ "labelExpressionInfo": { "expression": "$feature.name" } }]
}

The bridge writes the data to a file in the session folder. Then Claude calls update_layer to change the colors or the filter. The layer keeps its id and its data.

update_layer { "id": "L14", "definitionExpression": "score >= 7" }

9. Architecture

The data goes through these parts:

  1. Claude calls a tool.
  2. The tool.call hook in register.tsx gets the call. One hook serves all nine tools. It matches the RegExp /^mcp__arcgis-map__/.
  3. The hook keeps only the input fields in the tool schema.
  4. The hook sends POST /cmd {op, args} to the bridge with $.http.fetch.
  5. The bridge sends the command to each connected map page as a Server-Sent Event (SSE).
  6. Each map page does the command with the SDK.
  7. Each map page sends POST /ack with the result and its map state. The first correct answer is the result of the command. An error is the result only when all map pages failed.
  8. The hook returns the result to Claude.

The bridge also prints lines on its standard output. The mod reads these lines. They update the pane and the status line.

9.1 Lifecycle

  • The mod starts the bridge in the session.start hook: node web/server.mjs 8765.
  • The bridge stops when the mod stops or reloads. A reload starts a new bridge.
  • The bridge saves the map log and the view in ~/.claude/arcgis-map/sessions/<session id>/. A new bridge for the same session sends the map to the map pages again. This occurs after a reload and after claude --resume.
  • When the bridge starts, it deletes session folders that nobody used for 30 days.
  • When a map page opens, the bridge sends reset, then the map log, then the saved view. A map page that connects again gets only the commands that it did not get.
  • The bridge gives each new layer its id (L1, L2 and so on). Thus the ids are the same on all map pages.
  • A map page does one command at a time, in the sequence that the bridge sent them.
  • A map page does not answer the commands of the map log. It sends its map state one time, when the last command is done.
  • The bridge reads index.html one time, when it starts. A change to the page needs a new bridge. An open map page then reloads itself (section 9.3).

9.2 Map log and session folder

The bridge adds a command to the map log when the command changes the map. These commands change the map: add_graphic, add_layer, update_layer, remove_layer, clear_graphics and set_basemap.

The bridge does not add these commands to the map log:

  • go_to and screenshot. They do not change what the map holds. The saved view keeps the last center and zoom.
  • map_state. The bridge answers it. No map page gets it.
  • A command that failed on all map pages.

A command that no map page answered in time stays in the map log. It can still finish, so a map page that opens later must also do it.

Each event in the SSE stream has the id <epoch>:<n>. The epoch is 8 random hexadecimal characters. A new map log gets a new epoch. The value n is the number of the command in the map log.

  • A map page that connects again sends the last id in the header Last-Event-ID.
  • If the epoch is the same and the bridge knows n, the bridge sends only the commands after n.
  • If not, the bridge sends reset, the full map log and the saved view.

The mod gives the session id to the bridge in the variable ARCGIS_MAP_SESSION. With this variable, the bridge keeps these files in the session folder:

FileContents
map.jsonepoch, log (the commands) and view (center, zoom). The bridge writes a temporary file, then renames it.
data/layer-<epoch>-<n>.geojsonThe inline data of one add_layer command.
data/map-<time>.pngOne screenshot result. The time is in ISO 8601 format, with - in place of : and ..

Without ARCGIS_MAP_SESSION, the bridge saves no map log. It writes data files and screenshots in a new temporary folder arcgis-map-data-*.

9.3 Page version

A map page keeps its code until it loads again. When the bridge stops, the EventSource of the page connects again automatically. It does not load the page again. Thus, after a new bridge starts with a changed index.html, an open map page continues to run the old code.

The page version prevents this problem:

  1. The bridge starts and reads index.html.
  2. The bridge calculates the page version.
  3. The bridge writes the page version into the page in place of the text __PAGE_VERSION__.
  4. A map page connects to GET /events.
  5. The bridge sends the event version with the page version.
  6. The map page compares this value with its own page version.
  7. If the two values are different, the map page reloads. The new page gets the full map log.

A map page with the same version does not reload. Thus a reload occurs one time only.

A map page that opened before the mod had the page version has no version check. It does not reload itself. Reload it one time: push Cmd+R in its window, or close the window.

11. Pane internals

11.1 Pictures

  • The bridge starts the viewer when the pane sends its size.
  • The viewer is the installed Chrome with --headless, --remote-debugging-pipe and the Metal GPU flags --use-angle=metal --enable-gpu.
  • The viewer uses the Chrome DevTools Protocol (CDP) on the pipe. It uses no library.
  • The viewer sets the page size to 10 × 20 pixels per terminal cell.
  • The viewer starts the screencast after the page load event. An earlier start fails.
  • Each frame goes to one PNG file. The viewer writes a temporary file, then renames it. The terminal never reads half a picture.
  • The pane shows the file in an Image element. $.ui.blit changes the picture without a redraw.

11.2 Input

  • The pane tree has a Client element under the Image. The Image is in a Box with position="absolute".
  • The Client runs hooks/viewer-client.ts. It gets pointer and key events.
  • It sends presses, drags and releases. It does not send hover moves.
  • Each post has the last 32 events with sequence numbers, the region size and an instance id. A later post in one frame replaces an earlier post, so the sequence numbers prevent lost events.
  • The ui.message hook sends only new events to POST /input.
  • After a reload, the mod does not know the instance id. It then sends only events from the last second.
  • The viewer changes events to Input.dispatchMouseEvent and Input.dispatchKeyEvent. Two presses in 400 ms at one place make a double-click.

11.3 Recovery and idle stop

  • The Client sends a heartbeat every 30 seconds.
  • The bridge closes the viewer after 90 seconds with no request on /input. This releases 1.2 GB to 1.9 GB of memory.
  • If Chrome stops, the viewer deletes its temporary folder. The bridge prints VIEWER down.
  • The bridge closes Chrome when it gets SIGTERM or SIGINT.

11.4 State

AtomTypeShape tag
statusMapStatus: isConnected, layers, center, zoomstatus-2

Change the shape tag when you change a type in types/index.d.ts. The tag stops old values from a previous version.

12. Security

  • The bridge listens on 127.0.0.1 only.
  • The bridge refuses a request when the Host header is not 127.0.0.1:8765. This stops DNS rebinding.
  • The bridge refuses a request with an Origin header from a different site. This stops cross-site POST requests.
  • Open the map at 127.0.0.1. Do not use localhost.
  • The bridge serves only files that a command from the mod named. It serves no other path.
  • Each file URL has a random key (a UUID). A program that does not know the URL cannot get the file.
  • The mod makes a new random token each time it loads. It gives the token to the bridge in the variable ARCGIS_MAP_TOKEN. The bridge refuses POST /cmd and POST /input without the header x-arcgis-map-token. This stops other local programs, which the Host and Origin check does not stop.
  • The map pages need no token. Their endpoints only show the map and report its state.
  • The browser window uses a Chrome profile in the folder of the mod, not a shared path in /tmp.
  • The map page loads the ArcGIS SDK from js.arcgis.com. The SDK runs with the rights of that page.
  • The mod has no secrets, no API keys and no npm dependencies.

Limit: the bridge is for one user on one computer. A different user on the same computer can see the commands on GET /events.

14. Limits

  • The port is 8765. Only one map can run on one computer.
  • The pane picture assumes a terminal cell of 1:2. A different cell shape makes the picture wider or narrower.
  • The browser window goes on the right half of the screen. It does not align with the edge of the Ghostty window.
  • The pane works only in a terminal. Claude Code Desktop shows a link.
  • The mod has no tool to change the layer order.
  • When two map pages are open, the last answer sets the map state.
  • The map log only gets longer. A removed layer stays in the log as two commands.
  • A map page that opened before the page version check does not reload itself. Reload it one time by hand.
  • The pane picture has 10 × 20 pixels for each cell. A scale factor of 2 gives no sharper picture: headless Chrome sends the frame at the same size.

17. Headless browser benchmark

This benchmark selected the viewer setup. The map needs WebGL2. Lightpanda has no rendering engine, so it cannot show the map.

Setup: Chrome 153 headless, Apple M4 Max, page size 800 × 500, median of 3 runs, 9 November 2026.

SetupLaunchMap readyCommand to first framePan frames per secondMemory
Raw CDP, GPU318 ms1.30 s64 ms58.81.9 GB

puppeteer-core, GPU380 ms1.32 s50 ms58.71.2 GB
puppeteer-core, software390 ms3.15 s52 ms58.51.4 GB

Results:

  • The GPU flags decrease the time to a ready map from 3.0 s to 1.3 s.
  • The driver has almost no effect on speed. Raw CDP needs no dependency.
  • The viewer uses the quiet launch flags of puppeteer-core to decrease memory.
  • The screencast gives approximately 59 frames per second. One PNG screenshot takes 70 ms to 85 ms.
